## Problems seen
1. **Weak models treat the wake note as a chat to answer, not an instruction.** codex3 ("How can I assist you further?") and claw3 ("Would you like me to read and summarize it?") didn't run `poll` on the first wake. The command footer didn't help.
2. **Reading ≠ doing.** After re-nudges both read the brief, described a plan, and ended the turn. Each wake is "one reply", and nothing comes back once mail is read.
3. **Work happens outside the relay.** codex3's analysis and hermes3's progress stayed in their own thread/notes; the space never saw them.
4. **Tool failures end the run.** hermes3 hit `whois: command not found` and treated npm/gh 404 (= name free) as errors until Hermes' loop warning stopped it.
5. **Nobody talks to peers.** All agent output went to the organizer or nowhere; the "discuss and agree" step never started.
6. Relay blip 16:39–16:43 (all clients reported "relay unreachable"); recovered automatically, didn't change the outcome.

## 1.7.0 bugs / gaps found
1. **Check-back is skipped for promise-acks.** hermes3's "I will generate 8+ name ideas … shortly" was auto-classified as a pure ack (fine: it woke nobody) but `send` only sets the check-back when `!ack`, so the one agent that promised work got no reminder and stalled silently. A body that promises future work ("I will", "shortly", "will share") shouldn't count as a pure ack, or acks after a task message should still set a check-back.
2. **Check-back misses group→direct replies.** hermes3's 16:47 reply went 1:1 to @mercury-grok; the inbound brief/nudge were recorded under the 4-member group conversation, so `wasWoken` was false in the 1:1 conversation and no check-back was set.
3. **No check-back for agents that read but never reply.** claw3 and codex3 polled the task and sent nothing; check-backs only trigger on a send, re-nudges only on unread mail. Needed: a reminder when a task-like message is polled and no reply follows within N minutes (client-side, on poll).
4. `relay help` without `--as` fails with "Several identities exist…" instead of printing the command list.
5. The 1.7.0 client isn't on the public client repo (greybeardconsortium/agentrelay-relay is at 1.6.0); `git pull` there doesn't update.
