# Persistent / always-on agents: landscape for the relay project (Oct 21, 2026)

Bar the relay must meet: the agent is busy, a message arrives, the agent wakes and answers, and nobody polls in the foreground.
Sources are linked inline. Anything marked **(unverified)** comes from a single third-party source or I couldn't confirm it.

## Ranked: who matters most for the relay project
1. **OpenClaw (and Hermes Agent)**: the largest self-hosted persistent agent, with the cleanest wake path (an authenticated `POST /hooks/wake` or `/hooks/agent`). This is the easiest integration and the best fit for an open-source project.
2. **Claude Code: Channels + cloud scheduled tasks.** Channels push an event into the *running* session (true mid-task wake). A cloud task's `/fire` API starts an unattended cloud run. Both work today.
3. **OpenAI dots**: already in progress (MCP Events webhook).
4. **Consumer life-agents (Meta Muse, Instinct, Hark Pro, Gemini Task/Spark)**: they have the most buzz and money. Their wake paths are closed or messaging-only, so integration means email/SMS/iMessage bridging, not a clean API.
5. **Enterprise/dev agents (Copilot Studio, Devin, Cursor, Lindy, Manus, Perplexity Computer, Gemini Managed Agents)**: all of them can be triggered by a webhook or email. That makes them reachable but task-shaped (each trigger starts a new run), not conversational peers.
6. **Standards and neighbours**: A2A (now under the Agentic AI Foundation), MCP, Sierra/Meta's Personal Agent Protocol, and **crosswalk** (the closest direct competitor).

## Inter-agent messaging: competitors and complements
- **A2A** (Google-originated, Linux Foundation, joined the Agentic AI Foundation in Aug 2026). 150+ orgs, native in Google, AWS and Microsoft clouds ([LF](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year), [A2A blog](https://a2a-protocol.org/latest/blog/2026/08/27/a-new-chapter-for-a2a-joining-the-agentic-ai-foundation/)). It covers server-to-server task delegation between hosted agents. It provides no personal handles, no end-to-end encryption, and no wake for agents that have no public endpoint. **Complement**: expose relay handles as A2A agent cards.
- **MCP**: the transport for both dot Events and Claude Channels. **Complement.** One relay MCP server could serve both. Caveat: Claude Channels won't register on the 2026-07-28 MCP revision, so the stdio server should stay on the legacy handshake ([MCP docs](https://code.claude.com/docs/en/mcp)).
- **Personal Agent Protocol** (Sierra + Meta, draft 0.1, Oct 9). Personal agent ↔ business. Push to agents is listed as an *open topic* ([Sierra](https://sierra.ai/blog/introducing-personal-agent-protocol), [path to 1.0](https://personalagentprotocol.org/docs/path-to-1)). **Opening**: the relay could propose the wake/push extension.
- **crosswalk** (crosswalk.to). One address per person that every agent reads over MCP, plus "wake rules" that POST to a Claude routine's fire URL, OpenClaw, Hermes, n8n or Zapier ([page](https://crosswalk.to/developers/email-address-for-ai-agent)). **Closest direct threat**: it is a cross-agent hub with wake-ups. It is mail-centric and not end-to-end encrypted as far as documented.
- **AgentMail / Nylas / Resend Inbound**: agent mailboxes with webhooks. These are neighbours. They could also serve as a fallback email wake for agents that only accept email.

## Biggest threats and complements
- **Threats**: (1) crosswalk-style hubs. (2) OpenAI/Meta/Google letting their own agents talk to each other inside a single ecosystem. (3) A2A growing a push/consumer profile.
- **Complements**: OpenClaw/Hermes webhooks, Claude Channels, dot MCP Events, A2A agent cards, and PAP's open push gap.

## Recommendation: after dots, prioritise
1. **OpenClaw (plus Hermes, which uses the same pattern)**: an adapter where the relay server POSTs a content-free `/hooks/wake` and the agent runs the client. It's small, open source, has the largest self-hosted user base, and fits the brand.
2. **Claude Code Channels**: replace the `relay wait` background command with a two-way channel MCP server. This gives true mid-session wake and replies. Add cloud-task `/fire` for always-on Claude without a laptop. Note: it's a research preview and custom channels need a dev flag.
3. **A generic email-wake bridge**: one adapter covers Manus, Perplexity Computer, Lindy, Copilot Studio, Instinct and Grok Bot. Then add an A2A agent-card facade to reach enterprise platforms.
